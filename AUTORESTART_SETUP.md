# Автоматический перезапуск бота

## Подтверждённая причина
Проверен raw-файл `.github/workflows/run_bot.yml` ветки main репозитория
andrey9653246431-spec/find_job_in_www_bot: значение по умолчанию 60 минут,
расписание закомментировано, следующая сессия не запускается.
Приватные логи запусков и секреты недоступны: другие причины остановок не исключены.

## Установка — нужны ДВА действия
1. Загрузить `find_job_in_www_bot.zip` в корень репозитория, дождаться успешного Unpack.
   Это обновит Python-код и тесты, НО НЕ workflows: существующий Unpack специально
   исключает `.github/workflows/` из коммита из-за ограничений GITHUB_TOKEN.
2. Открыть `.github/workflows/run_bot.yml` на GitHub → Edit, заменить содержимым
   приложенного отдельно `run_bot.yml` (тот же файл находится внутри архива).
   Сохранить в main. Затем Actions → Run Telegram Bot → Run workflow.

Settings → Actions → General → Workflow permissions: разрешить Read and write.
Секрет BOT_TOKEN должен существовать. Токен бота никому не отправлять.
Если защита main запрещает push от github-actions[bot], heartbeat не запишется:
нужно настроить разрешения или выбрать постоянный хостинг.

## Поведение
- При завершении/ошибке polling: повтор через 5, 10, 20, 40, затем 60 секунд.
  Сетевая недоступность до запуска polling может прервать сессию целиком.
- В Actions сессия по умолчанию 120 минут; после неё сохраняется кэш БД
  и через API запускается следующая сессия. После ошибки запуска — тоже.
- Резервное расписание каждые 6 часов, только в default branch.
- Новые запуски ждут завершения активной сессии: schedule/push не обрывают
  сохранение БД. При обновлении кода подхват может занять до конца текущей сессии.
- Раз в сутки heartbeat-коммит в `.github/bot-heartbeat.txt` поддерживает активность.
- Отмена вручную не создаёт новую сессию по цепочке, но расписание остаётся!
  Для полного выключения: Actions → workflow → Disable workflow, затем отменить run.
- Изменения, запушенные GITHUB_TOKEN (в том числе Unpack), сами не вызывают push-workflow;
  после установки запустите workflow вручную. Следующая сессия берёт свежий main.

## 30 / 60 дней
Отсутствие входа в аккаунт 30 дней само по себе не останавливает workflow.
GitHub отключает scheduled workflows в публичном репозитории после 60 дней без
активности репозитория. Heartbeat предназначен поддерживать эту активность,
но зависит от разрешённого push. Если workflow уже disabled, включите его вручную.
Документация: https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule

## Ограничения
Это не гарантированный хостинг 24/7. Очереди, задержки/пропуски schedule, лимиты
Actions, сбои GitHub/Telegram и ошибки разрешений могут давать простой. Между
сессиями бот временно не отвечает. Кэш Actions — НЕ надёжное постоянное хранилище
БД: он может быть удалён; при отмене сессии последние изменения могут потеряться.
Для действительно постоянной работы предпочтителен VPS с systemd/Docker restart
и БД на постоянном диске, без зависимости от посещения GitHub.

## Проверка после установки
- В run видно лимит сессии 120 мин, а не прежние 60.
- После ошибки polling в логе появляется повторный запуск.
- В конце: Save SQLite → Restart next session → HTTP:204.
- В Actions появляется следующий run. Отправьте /start и /my_resume.
- На следующий день проверить свежую дату в `.github/bot-heartbeat.txt`.
- Предупреждение heartbeat/push или HTTP:403 нельзя игнорировать: исправить права.
